# 01 — Functional specification: Casevex
Contract version 1.0. Default locale en-US, Eastern time; timestamps stored UTC; no fictional legal data in production.

## Global product behavior
Onboarding: invited firm admin creates workspace with firm name and approved domains, authenticates with verified email + MFA policy, accepts terms/retention notice, chooses launch jurisdiction and practice areas; invites members (never grants matter access implicitly); creates first matter and explicitly assigns members; chooses agent profile; uploads document; starts research; optionally creates a monitored topic. New members see only accessible matters. Admin role does NOT override ethical-wall restrictions. Account's displayed job title is editable; authorization role is not.
Navigation: sidebar unread count and matter list reflect current authenticated user's access; direct links to unauthorized matters return generic 404. Search scope is explicit (my matters / assigned matter / public authorities). Never navigate to default sample matter. Current data must be scoped server-side, not filtered from an unrestricted bootstrap payload. Server paging, empty states, retry, stale-data notices, optimistic version conflict flows, disable/retry for pending writes. Toast success only after API success. Mobile stacked layouts and inner scrolling; preserve prototype style and source-grid motion. No fictional sample may be marked 'verified' outside fixture demo mode.

## Screen 01: Dashboard `/`
Displays greeting by user timezone; authorized active matters count/list; next **confirmed** deadlines; unread reviewed/uncertain updates with distinct badges; recent activity; ask-box (question, practice area, optional matter, jurisdiction). No matter selected -> creates general research workspace/thread with chosen authorized public corpus, NOT `anderson`. A matter selection automatically restricts confidential evidence to that matter. Change practice area -> agent-profile suggestion, not auto-changing matter jurisdiction. Submit -> POST research-run, show queued state, navigate run/thread, stream actual progress. 'Run agent', 'Research precedents', 'Analyze documents', 'Update strategy' open relevant UI; permissions gate each. Never display fake totals. One-time empty dashboard guides create matter and upload.
Failures: coverage outage appears only where it matters; don't show 'No updates' as equivalent to offline. Too many alerts -> digest and collapse.

## Screen 02: Notices `/notices` & matter notices
All/Unread/Rulings/Deadlines/Docket filters, counts, date, provider, affected authorized matters, read per recipient. Click opens existing right-hand drawer: linked legal event, original canonical authority/docket, extraction timestamp, update type, why matched, affected issue, support spans, tentative `strengthens|weakens|mixed|unknown`, status `proposed|needs_review|approved|dismissed`, reviewer, coverage. 'Review' is attorney-only; approve/dismiss requires explicit action and rationale (and may revise impact). Reading is NOT review. Settings alert preferences per-person and per-watch. Mark-read can operate on all visible authorized notices only; preserve per-user read state. Debounce digest and dedupe by event+matter+recipient. Missing licensing = source metadata-only; no fabricated full text.
Failures: inaccessible linked matter concealed; deleted watch shows historical notices with source reference; provider outage displayed on monitoring health.

## Screen 03: Matters `/matters`
Create/edit/close/archive with name, reference/docket, court, jurisdiction, practice area, party role, case summary, optional initial assigned agent, explicit members. Validation: duplicate names allowed, IDs unique; docket format informational (do not presume exact match); enforce allowed practice/jurisdiction options and member ACL; archive disables active monitoring by default with opt-back-in and approval. List tabs/filter/sort/search are server paginated and access filtered. Matter page: Overview (summary, assigned participants, last activity, confirmed deadlines, latest reviews), Documents, Research, Notices, Deadlines, Strategy, Chat. Missing permissions -> 404; edit conflict -> diff and reload. New matter defaults to zero documents, no fake metrics. Matter delete only retention/admin governed; ordinary action archives.
Overview: action links scoped matter; editable summary versioned and audited; display legal issue tags reviewed by attorney; monitor state summary and last source check.

## Screen 04: Matter Documents & global `/documents`
File upload: choose permitted matter, PDF/DOCX (expand formats only after parser testing), max 20 MiB initially. Browser obtains short-lived upload intent and uploads bytes directly to quarantine private object storage; finalize -> virus and MIME/signature checks -> parse/OCR selectively -> page-aware source mapping -> index. Display actual progression `pending/uploaded/scanning/extracting/indexing/ready/failed/quarantined`. Retry safe transient failures; corrupt/unsupported files actionable. Originals never publicly served; signed permission-checked downloads, preview with page-level search highlights and original OCR confidence; never send user raw service storage keys. Rename/change matter (revalidate recipient ACL, reindex/reauthorize), edit metadata, append immutable versions, restore prior version through new active revision, soft delete subject to hold, export authorized original. Drag/drop/attach while chat uploads into current authorized matter; processing state blocks use until ready. No actual client data in demo mode. Content dedup **within the same workspace + ACL boundary** only; identical hash never grants cross-tenant access.

## Screen 05: Matter Research & Chat
Research tab: saved threads/runs, research notes, saved authority citations, source inspection panel, filters by date/status/agent. Chat composer accepts a question, attach permitted documents, optionally choose issue and agent. Optimistically show question with client-generated id; server returns persisted run ID; on SSE receive progress, partially streamed answer, cited source ids. UI source tiles map real `located→fetched→passage_matched→checked` and source failures; no completed/green tile from elapsed time. Answers format concise bottom line, reasoning, support and contrary authorities, limits/uncertainties, suggested next step, source inspector. Source click -> actual authoritative URL or authorized original page/quote (server-owned ID, no AI-generated href). If no verified support, abstain and suggest research path, no invented case citation. Cancel/retry/reconnect resume; completed answers immutable with model/prompt/corpus version and timestamp. Export includes citations, review warning, run metadata and quote references; not a silently editable legal filing. Chat context only authorized matter docs/thread and approved legal corpora, strict bounded history. Visible agent selection can be overridden per research run without altering matter default (record actual version).
Global question (no matter) -> a general research thread and public-only retrieval, never private data by default.

## Screen 06: Agents `/agents`
Retain practice-area cards and assign modal. Add detail drawer with description, jurisdictions supported, allowed source providers, workflows, guardrails, last profile version, preview examples. Built-in profiles: Consumer fraud/class action (pilot), NY civil litigation, employment (beta after corpus), corporate/contracts/trust/real estate/regulatory as DISABLED UNTIL tested and data coverage established. Firm admin may clone enabled base profile into firm-scoped custom profile, choose permitted practice-area tags, instructions, answer format, source inclusion/exclusion, approved jurisdictions, monitoring defaults, and per-run spend ceiling within hard enforced policy. Cannot change safety/ACL/verification policy or request inaccessible legal sources. Version immutable once assigned; 'publish version' requires admin; rollback by assigning a prior validated version. Assign multiple authorized matters to profile; UX shows assigned count computed from database, current availability based on real system state (not arbitrary capacity). Attorneys can choose from firm-approved profiles and adjust allowed run-level workflow; avoid arbitrary prompt injection through custom instructions. Practice-profile changes don't modify historic answer provenance.
Onboarding selects a suitable profile; if unsupported ask to use explicitly labeled General legal research with clear corpus limits.

## Screen 07: Precedents `/precedents` and detail
Tabs `Search`, `Saved`, `Following`, `Updates`. Query case name, citation, phrase, court, jurisdiction, issue, date; qualified filters derived from indexed provider coverage (not hardcoded Federal only). Show original court, decision date, publisher, ingestion date, authoritative link, exact pinpoint spans, source existence verification separately from treatment. Detail includes canonical metadata, original readable opinion where permitted, search passages, cited-by relationships where reliably observed, scoped matter associations and alerts. Buttons Save to matter, Follow authority, Create topic watch, Review potential treatment. Citation entered by user initially `unresolved` until provider lookup; no guessed opinion. `Good law` must not appear unless licensed complete treatment and attorney-reviewed scope; default 'Treatment coverage incomplete'. Later citing case is NOT necessarily negative treatment.
Source missing/withdrawn/corrected => version lineage and prominent change badge. Results show corpus coverage and last checked time.

## Screen 08: Calendar `/calendar` and deadlines tab
Month/agenda, authorized matters only. Event types due date, hearing, meeting, task; date-only vs timed event distinct, IANA timezone. Create/edit/cancel with optimistic version and actor permissions; validated recurring reminders (in-app first, email opt-in), no auto legal deadline computation or automatic external calendar sync initially. Potential dates extracted from document are 'suggested, unconfirmed', excluded from authoritative countdown until attorney confirms source/date/timezone. Notice and audit on changes, reminders deduplicated. Daylight saving and overdue relative date correct by local date; no frozen TODAY fixture in production.

## Screen 09: Settings
Profile: name/email/timezone/default practice area/appearance preference; email change verified by identity provider. Role/job title display cannot alter ACL. Workspace: firm metadata, membership/invitations, licensed jurisdictions, retention/holds, feature flags accessible only to proper admin; member list alone never grants matter access. Notifications: in-app/email, immediate critical-review vs daily/weekly digest, quiet hours, per-topic frequency, unsubscribe without deleting audit. Integrations: legal provider coverage status, connection timestamp, failure health, DMS/calendar placeholders unless enabled. Security: MFA, session revoke, user activity, scoped audit export, API keys managed server side. Billing/usage optional pilot administrator summary, not fake invoicing. Dark preference may remain pending until styled and tested.

## Screen 10: Global cross-cutting flows
Global search can federate *authorized* matters, documents and public authorities; each result carries scope and type. Shortcut search never exposes inaccessible matter titles, even in counts. Keyboard accessible modal focus trap and restore; back/forward URL state; loading skeletons not fake results; retry with request id; toast calls distinguish draft vs completed action. Invitations are sent only after server creates token hashed at rest and user confirms send. Docket watch is only enabled for licensed/provider-supported courts; disabled feature visible with explanation. Audit each read of protected doc/extract, export, assignment change, search/run and alert review.

## State machine and empty/error state rules
Research: `queued→running→completed|failed|cancelled`; `running→cancel_requested→cancelled|completed` if provider completes first. Documents: `pending→uploaded→scanning→extracting→indexing→ready` or quarantined/failed. Alerts: `candidate→proposed→approved|dismissed`, needs_review if verification ambiguous; only approved alerts described as attorney-reviewed. Monitoring: active/paused/coverage_degraded/disabled. Agent profile: draft/published/deprecated. Each state requires distinct UI text, prohibited actions and permitted recovery. `0 results` vs `source offline` distinct.

## Business rules / safeguards
No autonomous legal filings, individualized legal-advice representations, hidden unsupported jurisdictions, auto-confirmed legal deadlines, attorney replacement, unscoped private data sharing, unlimited agent tooling, or false comprehensiveness. Legal insights can be proposed, never auto-adopted into strategy. Maintain immutable provenance and audit log. Accessible UI should use text labels as well as colored indicators.
