# 02 — Architecture, domain model, data security, infrastructure

## Deployment architecture / boundaries
- Browser -> Next.js 16 BFF/routes on Vercel (or replaceable Node host); never expose service/admin credentials or raw DB access in browser.
- Next.js BFF -> authenticated Supabase Auth and PostgreSQL (single database; force per-workspace query policies). Supabase Storage private buckets `quarantine`, `matter-originals`, `derived`; signed short-lived upload/download only after ACL check. No public bucket for client content.
- Next.js BFF -> private Python FastAPI research service (request authentication via service identity + signed scoped user claims including workspace, matter, capability and expiry). Python never directly trusts client-provided workspace IDs.
- Durable workers: Trigger.dev or equivalent non-ephemeral worker runtime for scan, extraction, OCR, index, corpus updates, alert generation and dispatch; queue messages contain IDs not full confidential text; workers re-check grants before private retrieval and publish results into scoped tables.
- Email: transactional provider adapter, default disabled in local mode. Outbox + dead-letter queue; never put client factual summaries in email unless firm/user opts in; default metadata-only digest.
- One PostgreSQL full-text search index with workspace/matter ACL; optional pgvector only after benchmark. Legal public authorities and private user documents are distinct collections/tables/index paths.
- Secrets via deployment secret manager, dev `.env.example` placeholders only. Service-to-service auth, network segregation, TLS, explicit egress allowlists for legal providers and models; retention controls for LLM provider. No telemetry containing client excerpts/prompts by default.

## Authorization contract
Identity from verified JWT/session, workspace selected from accessible memberships, matter grants checked on every operation. Explicit capabilities: `matter.read|write|share|review`, `document.read|upload|export|delete`, `research.run|view`, `authority.save`, `impact.review`, `agent.assign|configure`, `settings.manage`, `audit.export`. Admin membership may administer users without access to ethically walled matters. Agent assignments never convey extra read permissions. Retrieval/exports/preview/search/cache/SSE/notification payloads MUST filter on `workspace_id` + matter grants. Cross-matter queries require separate explicit authorization and scope; default off.
Postgres RLS: FORCE where appropriate, default deny; separate restricted service DB roles for background tasks (avoid bypassrls owner for ordinary queries); dedicated signed worker operation scope; test RLS with actual non-owner DB role. Never trust client-supplied `workspace_id,user_id` for grant checks. Blob object keys opaque and not user-enumerable. Validate authorization at signing and at access to generated extracts.

## File pipeline
Upload intent: require matter upload, filename normalized, bytes <= 20MiB, declared mime + hash and quota. Intent stores planned object key and expires within 10 min. Direct-to-quarantine; finalize verifies size/hash, magic MIME, scan result and authorized intent. DOCX unpack zip-bomb guards, PDF parser sandbox, OCR pages only when needed with bounds/time limits; extraction captures coordinates/line numbers and confidence. On success copy to originals, derive page spans, chunk & index, store byte/version checksum; failures return retryable codes; malware quarantined and cannot retry without new upload. Change matter = move via controlled transaction + index purge/rebuild; revocation immediately removes query access. Long-running job idempotency keyed by version checksum. Deletion honors hold and retention, purges derived indexes and pending work.

## Research orchestration
BFF authenticates, checks quota/ACL, inserts run + outbox in transaction, returns 202. Worker reads run, resolves versioned agent, checks source permissions, gathers candidate authorities and page chunks, reranks, generates bounded structured answer, independently validates source existence and quote/claim support (checks separate), commits answer claims/sources, emits `run.completed` only after durable commit. Stream events retained with increasing seq and SSE resume via Last-Event-ID. A cancelled run must not silently resume; record usage. Model fallback only among approved providers with equivalent privacy/data terms and evidence constraints. Sources cannot introduce new instructions (prompt injection boundary).

## Data retention and incidents
Per-workspace configured policy with default documented pilot retention; hold supersedes deletion. Store backups encrypted; periodic restore drills and RPO/RTO measured and recorded before launch. Audit retention independent of document deletion where legally permitted; avoid preserving secret content in audit. Secrets rotated, account deprovisioning revokes session and signed URLs quickly (short TTL). Provider failures -> health state; no stale completion masquerade. Use Sentry or equivalent with content scrubbing, health metrics queue lag, failed ingestion, model errors, provider errors, usage budget alarms. Budget limits per workspace, per-run hard ceiling, rate limiting. Never promise HIPAA/ISO/SOC certifications that aren't obtained.

## Environment and local development
`local`: synthetic sample labeled and isolated; adapters to mock HTTP services; no genuine legal-source guarantees.
`staging`: own Supabase project, sample/sanitized data, provider sandbox, negative ACL tests, no production credentials.
`production`: real auth, live data providers subject to approved contracts, client data encrypted, migrations applied, fixture mode disabled. Expose `GET /health/live`, `GET /health/ready` separately, with no secrets. Require migration checks and config validation at deploy. Feature flags `legal_monitoring_enabled`, `document_ocr_enabled`, `email_enabled`, `vector_search_enabled` (off until validated), `custom_agents_enabled`.

## Versioning / compatibility
Shared contract package consumed by Next.js; Pydantic/OpenAPI generated client or generated TS schemas (one source of truth). Each resource version for optimistic update; no breaking field changes without API version bump and compatibility tests. One canonical source-ID map. Make integration adapter interfaces for legal providers, email, auth, storage, model, vector search and queue, with contract tests.

## Launch security acceptance
No cross-user/firm leakage including search counts, embeddings, caches, SSE, signed URLs, exports or errors; secrets absent from logs and Git; upload malware/zip-bomb tests; webhook HMAC and replay handling; audit export permission tests; restore test; resilience to queue duplicates and retries; provider data retention review; professional legal/cyber counsel review before client confidentiality is entrusted.
