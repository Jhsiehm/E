# Casevex visual and motion direction

## Preserved from the desktop wireframes

Warm paper, navy navigation, Times/serif typography, rose actions and unread indicators, olive completion and deadline surfaces, compact square geometry, thin rules, and internally scrolling panels. The ten supplied screens remain the navigation backbone. Numbered annotation markers are omitted from the app itself.

## Integrated from the phone prototype

- **Source-by-source tile progress.** The 4×4 mark expands into a row-per-source research indicator. Tiles fill rose while reading and olive after each simulated check; a named source and count explain the motion. The actual backend will drive it with run events, not a timer.
- **Paper material.** The supplied paper texture is used subtly behind the workspace. The original olive texture grounds the next-deadline panel. Source cells use the supplied olive and rose pixel textures.
- **Spatial continuity.** Notice details arrive as a right-side drawer on desktop and a bottom sheet on phones. Timing follows the reference's 280 ms deceleration.
- **Small acknowledgments.** Toasts rise into view after an action; the logo's squares assemble once. Routine navigation is never held behind a splash animation.
- **Reduced motion.** Source status remains readable; artificial reading/streaming delays are shortened and spatial/looping animation is removed. Active animation pauses while the page is hidden.

Settings → Profile → Preview research animation provides a replayable demonstration. Sending a message in Anderson's Agent chat runs the integrated sequence.

## Positive qualities worth extending next

1. **Editorial hierarchy.** A clear answer, supporting reasoning, then evidence is easier to review than a wall of chat. Keep short summaries prominent without replacing conditional analysis with overconfident one-word verdicts.
2. **Evidence as the central interaction.** The tile identity is memorable because it explains work. Pair future real verification with clickable page excerpts, timestamps, and review status.
3. **Deadline-first focus.** The phone reference makes the next action immediately legible. A later mobile home iteration can prioritize a single deadline, due-soon matters, and research entry.
4. **Tactile restraint.** Paper and fine rules suit long reading sessions; limit texture to backgrounds so dense tables and citations remain crisp.
5. **Thumb-friendly navigation.** The phone's Cases / Research / Alerts bottom navigation is a strong future mobile variant. The current prototype retains the requested horizontal full-app navigation so all ten screens remain immediately accessible.

## Deliberate boundaries

No automatic interruption banners, recurring logo waves, autoplay splash delays, or simulated security/privilege claims. No real legal verification is implied by a green tile. The phone's unrelated sample matters and legal conclusions were not imported into the desktop seed corpus.

The textures in `public/textures/` came from the user-supplied phone export. The original export runtime was not shipped in the app. These are source-derived design assets, not newly generated images.
